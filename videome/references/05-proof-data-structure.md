# Proof, Data & Structure

## 25. Checklist
**Use/context:** Show a process, criteria, or completed benefits as an easy-to-scan sequence.
**Build:** Use 3–5 short, parallel items; reveal one line/check at a time; keep checked state visible while later items appear; end on a completed list and a clear takeaway. Never mark a claim verified without source support.
**Agent 3 build brief:** Build a concise checklist from approved facts in the brief. Reveal in order with clean check states, preserve exact claims, and flag any unsupported item rather than presenting it as proven.

## 26. Headline wall
**Use/context:** Convey scale of press coverage, research, or multiple proof points at a glance.
**Build:** Arrange a grid of actual headlines/quotes; establish consistent cards and source labels; move a highlight or focus across 2–4 representative items; finish on the most relevant one. Use licensed/approved content and don't fabricate publications.
**Agent 3 build brief:** Build a headline wall only from supplied or verified source material. Preserve exact wording, outlet/date attribution, and legibility; do not invent quotes, logos, or coverage.

## 28. Chart grow
**Use/context:** Explain a real metric or comparison with one clear animated chart.
**Build:** Choose chart type matching the data; set scale/units and labels; animate bars/lines from the true baseline; show values and source/timeframe; hold the final comparison long enough to read. Never animate beyond data.
**Agent 3 build brief:** Build an accurate chart-grow animation from the supplied dataset. Preserve units, baselines, category order, source, and timeframe; validate plotted values against input before rendering.

## 37. Progress bar
**Use/context:** Show completion, elapsed time, steps, or a deliberately advancing narrative.
**Build:** Define what 0% and 100% mean; keep a persistent track and legible label; animate at a pace tied to actual duration/completion; pause at meaningful milestones. Avoid false completion claims.
**Agent 3 build brief:** Animate a progress bar whose endpoint and meaning are explicitly supplied. Use truthful milestone values and timing, keep the label readable, and do not imply actual app progress unless linked to real data.

## 38. Counter ticker
**Use/context:** Make a real quantity feel immediate—sales, saves, elapsed time, or a numbered list.
**Build:** Use supplied verified start/end values and units; interpolate smoothly with separators; align changes to narration/event; stop exactly on the true final value and hold. Avoid fake live counters.
**Agent 3 build brief:** Build a counter ticker from the specified data, with correct units and final value. Do not invent real-time growth; make the number change explainable and easy to read.

## 39. Comment wall
**Use/context:** Show multiple audience reactions, questions, or user feedback as a social-proof montage.
**Build:** Use a few actual approved comments; arrange cards with readable hierarchy; move focus to one quote at a time; redact names/avatars as required; end on the insight, not a mass of tiny text. Never fabricate testimonials.
**Agent 3 build brief:** Build a comment wall using only supplied, permission-cleared comments. Preserve meaning, protect personal data, keep selected comments legible, and avoid invented engagement metrics or endorsements.
