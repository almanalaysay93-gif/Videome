# Four-Agent Dispatch Brief

Copy this shared context into each role's task. Keep private user details out of research searches unless the user explicitly asks to use them.

```text
PROJECT / BRIEF ID: [short name]
USER'S INITIAL IDEA: [verbatim summary]
CURRENT CREATIVE BRIEF: [approved/provisional; link or text]
GOAL AND AUDIENCE: [goal; audience]
PLATFORM / SPECS: [platform, aspect ratio, duration, resolution/fps if known]
EXACT COPY / CLAIMS: [copy; substantiation source for claims]
ASSETS / BRAND RULES: [paths; approved logos, UI, footage, palette, type]
SELECTED TECHNIQUES: [numbers/names from the 45-technique library]
OUTPUT LOCATION: [shared project folder; unique subfolders for research/build/review]
OPEN QUESTIONS / CONSTRAINTS: [unknowns, privacy, rights, deadline]
```

## Role assignment

- **Agent 1:** Use the initial idea to interview and brainstorm with the user; return an approved brief and success criteria.
- **Agent 2:** Start from provisional context in parallel; collect 3–7 relevant samples, with verified links and timestamps. Use Agent-Reach only when installed/healthy; otherwise label any authorized native-search fallback.
- **Agent 3:** Own the plan, build, and master timeline; combine approved brief, sample pack, and Agent 4 notes.
- **Agent 4:** Produce an anti-generic design checklist and targeted repo findings; review the plan/render; return PASS or prioritized FAIL findings with acceptance tests.

## Revision handoff

```text
JUDGE STATUS: [PASS / FAIL]
EVIDENCE: [timestamp/frame and observed issue]
SEVERITY: [critical / major / minor]
FIX: [one specific change]
ACCEPTANCE TEST: [observable condition for the next judge pass]
PRESERVE: [approved parts not to disturb]
```

Agent 3 revises only affected areas, re-renders, and returns the new output and evidence to Agent 4. Repeat until PASS or a genuine blocker requires user input. Deliver to the user only the passed final product and concise handoff notes.
